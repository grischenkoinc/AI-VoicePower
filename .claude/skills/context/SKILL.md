# /context

Занурює нову розмову в поточний стан проєкту AI VoicePower (публічно "Diqto"), не витрачаючи токени на повторне дослідження коду, git log чи Play Console.

**Це перший крок будь-якої сесії в цьому проєкті, а не опційна дія на запит.** Якщо перше повідомлення юзера в новій розмові стосується цього проєкту (незалежно від формулювання — "давай зробимо уроки", "полагодь баг у X", "що там з ФОП" тощо) — виконати цю навичку МОВЧКИ як підготовчий крок, перш ніж відповідати по суті задачі.

## Що робити

1. Завжди прочитати `Context.md` (хаб) у корені проєкту.
2. За змістом задачі користувача (якщо вже озвучена) або на власний розсуд, якщо неясно — прочитати релевантні тематичні файли:
   - `Context-Code.md` — для будь-якої кодової/архітектурної задачі
   - `Context-VoiceAnalysis.md` — для задач про промпти Gemini, аналіз мовлення, оцінки, AI-коуча
   - `Context-Courses.md` — для задач про контент курсів/уроків
   - `Context-Improvisation.md` — для задач про розділ "Impro" (Debate/Sales/Interview/Negotiation/Presentation/Storytelling)
   - `Context-Business.md` — для задач про Play Console, монетизацію, ФОП/податки, ReseraAI. **Цей файл у `.gitignore`** — може бути відсутнім на чистому клоні; якщо його немає, це нормально, просто не має локального бізнес-контексту.
3. Якщо задача користувача ще не озвучена (навичку викликали "наперед") — прочитати всі тематичні файли, вони короткі.
4. Дати користувачу **короткий** підсумок українською (3-6 речень, не переказ файлів дослівно): що завантажено, поточний статус з таблиці в `Context.md`, і чи є щось, що виглядає застарілим/підозрілим і варте перевірки (наприклад, якщо файл давно не оновлювався, а йдеться про щось, що могло змінитись — типу зовнішнього процесу в Business-файлі).
5. НЕ вважати ці файли за живий стан коду — це знімки на момент останнього `/handoff`. Для конкретних тверджень про поточний код (чи існує функція, чи актуальна версія залежності) — звірити з реальним файлом, якщо це важливо для задачі.
